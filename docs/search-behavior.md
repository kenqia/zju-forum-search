# 检索行为与实现边界

本页记录当前实现的检索规则、模型数据边界和站点适配细节。安装与常用设置见 [README](../README.md)。

## 登录与 WebVPN

通过学校 WebVPN 访问 CC98 时，扩展也会在[该 CC98 映射页面](https://webvpn.zju.edu.cn/https/77726476706e69737468656265737421e7e056d22433310830079bab/)显示入口。请先在 WebVPN 和 CC98 完成登录，再刷新映射页面。扩展在该页面复用论坛自身请求携带的短期授权，并通过 WebVPN 发出搜索请求。授权只留在页面脚本内，不写入扩展存储或发送给模型。结果链接也留在 WebVPN 中。

桥接只接受固定的 CC98 搜索接口和参数，最多并发一条请求，并限制持续请求速率。同页面脚本仍能触发桥接事件，桥接无法认证事件的发送方。若仍提示无法复用登录态，请使用校园网或 RVPN 直连。WebVPN 登录及搜索已由用户手动确认，桥接限流改动仍需在真实会话中复验。

扩展复用当前站点登录态，没有账号输入入口。CC98 使用原站短期授权，朵朵使用原站微信扫码登录后的授权。遇到未登录或登录过期时，先在原站完成登录，再刷新页面。

## 模型主机权限与本地密钥

保存时，浏览器只申请 base URL 所在主机的访问权限。API key 保存在 `chrome.storage.local`，该存储并不加密。service worker 用 key 请求 `{base URL}/chat/completions`，但不会把它回传给 content script。key 不会写入站点页面的 light DOM、日志或仓库。

## 搜索边界

### 请求与运行

CC98 请求间隔为 2 秒，朵朵初始间隔为 500ms；两者默认每页请求 20 条。一次搜索最多发出用户设置的 1 至 100 次站点请求，分页也计数。朵朵的间隔未经真实会话验证，遇到验证码或限流会停止。

达到请求上限、模型判断停止、没有新证据、用户手动停止或出错后，面板保留已有结果并说明原因。关闭面板不会停止搜索。关闭“允许模型提前收窄搜索范围”后，反馈轮仍可判断候选和提出新检索词，但 `should_stop` 与 `stop_queries` 不会改变本次运行的调度；设置在下一次搜索开始时读取并固定。

“停止并查看结果”只终止当前和后续站点请求。如果已有至少两条主结果候选且开启了最终列表重排，扩展会用独立的取消范围执行一次重排。重排开始后，操作按钮改为“取消最终列表重排”。取消会立即恢复完整的本地预排序，不删除候选，也不改变原有的搜索停止原因。重排超时、失败或返回无效结构时使用相同的本地回退。

再次提交查询会替换整个旧运行。扩展会取消旧运行未完成的站点检索、反馈调用和最终列表重排；旧请求之后返回的成功、失败或取消响应都不会改动新运行的结果和状态。

### 检索词与分页

“检索详情”中的词条不显示前导符号，显示的检索词与实际发送给搜索接口的内容一致。

CC98 的标题检索会引导模型优先用空格分隔组合词，例如“微积分 历年 试卷”；“微积分”“回忆卷”等完整词仍保持原样。直连和 WebVPN 使用同一条规划规则。

首轮模型先返回基础检索词，再另行追加有根据的简称、别称和同义词。扩展把新增词接在基础词后，按检索词去重；新增词不会覆盖基础词。没有可靠叫法时可以不追加。反馈轮也可以从候选的原生标题补充新叫法，仍按原有证据和救援规则校验。所有检索词共享站点请求次数上限，因此预算不足时，排在后面的新增词可能不会执行。

搜索按波次推进。首轮计划为检索词标记 `precise`、`balanced` 或 `anchor`。标题来源在请求上限允许时，先让模型顺序中最靠前的一个 `anchor` 和一个非 `anchor` 各取一页；查询角色不参与候选排序。组合缺少任一角色时仍执行已有检索词，并在进度区提示。后续波次先执行通过校验的新检索词，再公平推进已有检索词的分页。同一检索词在一个波次中最多请求一页。首次请求和分页共用同一个站点请求上限，也沿用来源的请求间隔、游标保护和时间提前停止规则。

反馈可以返回 `stop_queries`，让本次运行停止某个已经执行且仍有 continuation 的检索词。每项包含 `query` 和仅用于诊断的 `reason`。浏览器只删除匹配分支的 continuation，不取消其他分支，不撤销已入队首页，不消耗请求次数，也不把高命中分支放进“未命中检索词”。未执行、已耗尽、空白、重复和无法匹配的 query 会被忽略。`should_stop` 仍只关闭未来扩展，已知分页继续执行。旧 `stop_suggestions` 字符串在兼容期可读，但新模型只使用 `stop_queries`。模型自动收窄开关关闭时，两类停止信号都被本地忽略；来源耗尽、时间提前停止、请求次数上限和用户取消仍然有效。

CC98 搜索结果按发布时间倒序返回；当查询带明确起始日期且某页全部结果的发布时间都已知并早于该日期时，扩展停止该检索词的后续翻页，不影响其他检索词。朵朵按热度排序，不做这一提前停止。

### 反馈与排序

搜索正常结束后，扩展默认从主结果候选中取本地预排序前 M 条，发起一次最终列表重排。模型返回相对顺序和明确移除建议。相关性等级 1、2 和 3 只参与排序；只有请求发出前仍未判断的候选可以删除。相关性等级 0、时间范围外候选和 Top-M 外候选不进入请求。Top-M 外候选保持本地顺序。主结果候选为零条或一条、新查询替换旧运行，以及关闭开关时会跳过这次调用。

最终列表重排发送原始查询、运行内临时键、原生标题、发布时间、板块、回复数和三项检索事实。三项事实是最多 5 个按首见顺序保留的命中检索词、基于完整观察集合计算的独立检索词数量，以及全部合法正位次中的最佳来源位次。没有已知位次时发送 `null`。作者和相关性等级留在本地，等级继续保护删除语义。请求不包含必须概念命中、轮次、URL、正文、回帖、片段、平台标识或认证数据；朵朵正文派生标题发送为空。planner 接收前和最终序列化时都会执行字段白名单。模型超时、网络失败、非法 JSON 或无法识别的响应结构不会改变本地预排序，重复键和未知键会被忽略，遗漏的 Top-M 候选按本地顺序追加。

首轮模型调用会发送用户查询和浏览器当前日期。反馈轮从待判断候选中选择有限证据，一次返回相关性等级、后续检索词和停止判断。每条后续检索词声明 `query` 或 `evidence` 依据。证据依据扩展引用本次 Feedback 负载中的 1 至 3 个候选键，且支持候选必须有原生标题。支持集合包含等级 2 或 3 时按普通扩展接受；全部为等级 1 时必须声明 `clue_only: true`；任一支持候选为等级 0 时拒绝。浏览器只核对来源关系、当前等级和标题可见性，不检查扩展词是否为标题子串，也不做本地语义相似度判断。无效条目单独丢弃。

候选按最新独立证据所属检索词轮转，每个检索词先争取 2 条，剩余容量再按本地预排序补满；这不是每个检索词的永久上限。存在有新独立证据的 grade 0 候选时，每次反馈至少保留 1 个翻案名额。用户设置的候选数量只规定最多选择多少条，4000 UTF-8 字节上限优先。负载先装入原始查询、当前日期、剩余站点请求数、Search Ledger 和已执行检索信息，再用剩余空间装候选证据。某条候选放不下时，系统跳过它并继续尝试后面的候选。未选中或未装入负载的候选仍可进入后续反馈。只有相关性等级 0 会进入默认折叠的软隔离区域，相关性等级 1、2、3 和未判断候选留在主列表。候选被不同检索词再次命中或模型可见元数据变化后可以重判；同一检索词下只有位次变化和只有作者变化都不会触发重判。

浏览器先执行时间硬约束，再对主列表做确定性的本地预排序。相关性等级 3 排在等级 2 前，等级 1 与未判断候选同级。同一等级内依次比较排除词、必须概念、不同检索词命中数、来源最佳位次和首次命中轮次。模型阶段关闭、取消或失败时，界面完整保留这个顺序。

反馈模型收到剩余站点请求数、已执行检索词和每个已执行分支的 Search Ledger。Ledger 记录页数、累计原始命中数、分支去重候选数、最近一页的全局新候选数、当前等级 2/3 与等级 0 的候选数，以及 continuation 状态。候选证据只包含运行内临时键、最多 3 个不同检索支持、原生标题、发布时间、板块和回复数。作者、URL、平台标识、候选来源位次、轮次、片段、正文、回帖、认证数据和用户身份都不会进入负载，正文派生标题发送为空。完整负载不超过 4000 UTF-8 字节。板块可以帮助判断相关性，但不能提供标题检索词；回复数不能单独提高相关性等级。所有模型调用都关闭思考模式，将最大输出限制为 1200 tokens，并通过 `AbortController` 在 20 秒后终止。反馈超时、网络错误或无效响应会停止迭代，保留未软隔离结果，并跳过最终列表重排。

### 兜底与时间条件

扩展会在本地规范化模型计划：缺失的说明字段和空约束使用默认值，字符串形式的检索词转换为标准结构，缺失或未知的查询角色按 `balanced` 处理，空的必须概念会被丢弃。规范化后仍没有可用检索词时，纯单关键词直接按用户原词搜索，并在进度区说明已启用兜底。网络错误和模型超时不会触发原词兜底。

用户明确写出“近三年”“2025 年”“去年”等时间条件时，扩展会在本地校验模型给出的起止日期，并从主结果、软隔离区域和反馈证据中移除确定在范围外的帖子。发布时间未知的帖子继续保留。没有明确时间条件时，扩展不按发布时间过滤。面板分别显示主结果、软隔离结果和时间范围外结果的数量。

## 搜索源边界

CC98 的认证读取、请求、响应解析和分页位于 `frontend/src/extension/sites/cc98/`。界面通过 `source-registry.ts` 按页面地址选择 adapter，再创建搜索 session；界面不接触论坛 token。朵朵 adapter 位于 `frontend/src/extension/sites/duo/`，负责 `ddtk`、加密信封、快照分页与响应映射。manifest 已登记两个站点及其 API 主机，后台按 registry 校验消息来源。

计划缓存和“换一组检索词”入口已按 issue #10 的验收反馈撤回，再次提交查询会重新搜索。SearchSource 接手审查及朵朵接入前的未决项见 [审查记录](research/search-source-handoff-review.md)。

core 将候选对象、每次召回观察与排序文档分开保存。同一帖子被多词命中时，排序会使用所有文档中的本地片段，并从观察记录计算跨词命中和位次。结果卡片不携带内部排序键。

反馈证据在 core 内构造，进入 planner 前已去除 ID、URL、片段和召回记录，并按用户设置限制为 10 至 100 条。实际模型请求再次执行字段白名单和 4000 UTF-8 字节上限。正文派生标题只在本地显示，反馈标题为空；CC98 的原生标题反馈行为不变。

planner 的首轮和反馈提示词由 `SourceCapabilities` 生成。CC98 使用标题匹配与普通关键词，首轮提示会要求一个宽锚点和一个非宽锚点；朵朵使用全文匹配与普通关键词，这一能力仍需登录后对照原站验证。空候选与弱信号救援统一走 Feedback；全文匹配不改变正文不出域规则，反馈缺少原生标题时模型只能依据查询、命中数与允许的元数据继续规划。

`frontend/src/extension/feedback-payload.ts` 集中维护反馈白名单、标题来源检查及条数和字节上限；`text.ts` 提供归一化与大小写折叠函数。搜索源能力通过扩展消息传给后台 planner，后台只接受已声明的能力枚举。

新增 adapter 时，在 `source-registry.ts` 注册，并将其 `pageMatches` 和 `apiHosts` 分别登记到 manifest 的 `content_scripts.matches` 与 `host_permissions`。运行 `cd frontend && npm test -- src/extension/source-manifest.test.ts` 检查所有已注册源的权限是否齐全。测试按声明的模式字符串检查包含关系，允许 manifest 保留额外的模型端点权限；不解析更宽通配符是否等价覆盖。

## 朵朵适配现状

朵朵显示标题由正文截断生成，只供本地展示；模型反馈标题为空。扩展默认省略 `group_id`，不读取用户资料、不硬编码学校编号，也不继承原站的圈层筛选。搜索范围、`ddtk` 与 `duo_session` 的关系、未登录空结果含义、`needCode` 条件及阈值均需本人会话确认。协议与实现取舍见 [API 调研](research/duo-alumni-api-survey.md) 和 [实施记录](experiments/issue-18-19-duo-adapter.md)。

本轮交付复核见 [#12–19 结案记录](experiments/issues-12-19-closeout.md)。平台内部认证标识关系、空结果原因及风控阈值等未知项由开发侧保留，用户无需为日常使用验收查看凭据或主动触发风控。
