# 查询时检索可行性实验

## 问题

在不建立全站索引、不使用回帖发现主题帖的前提下，有限次 CC98 关键词搜索能否支持通用自然语言查询？

本实验先测候选主题帖召回，再测排序。候选不足时，重排算法和界面改进都不能补回缺失主题。

## 接口边界

- 全站搜索：`GET /topic/search?keyword=...&from=...&size=...`
- 板块内搜索：`GET /topic/search/board/{boardId}?keyword=...&from=...&size=...`
- 每页请求 20 条。扩展先让每个检索词获得一页候选，再在剩余时间中继续分页。
- 请求顺序执行；遇到 `401`、`403`、`429`、WebVPN 登录跳转或超时后停止。
- 搜索阶段不批量读取回帖。必要时只为前五条候选读取主楼。

服务端匹配字段和频率限制没有公开说明，必须在已授权环境中测量。

## 查询规划器

已完成的对照：

1. 原句基线：把完整自然语言原句作为唯一关键词。
2. 本地通用规划：浏览器分词会拆开领域短语，并产生低价值的相邻词组合。它只保留为失败对照，不再追加样例规则。

后续比较：

3. Qwen3.8-27B 查询规划器，作为下一阶段的主要方案。实验期它通过本地 FastAPI 调用 OpenAI 兼容接口（该后端已删除），只接收查询，不接收个人背景或论坛内容；当前扩展由 service worker 直连用户配置的端点。
4. 扩展内轻量本地模型。等第三方方案完成检索可行性验证后，再评估它能否用可接受的效果换取更强的隐私和离线能力。

所有规划器使用相同的时间预算、请求间隔、分页方式和候选合并方式。规划器生成的检索词和最终候选不设固定数量上限。

## 查询集

- 开发集：15 个查询，课程资料、实习岗位和年级事项各 5 个。
- 盲测集：30 个未参与调试的查询，覆盖课程、求职、校园事务、技术讨论、生活经验和兴趣活动。
- 变体覆盖口语、缩写、同义表达、长句和排除条件。

真实查询、候选标题、链接和人工标签只保存在本机。仓库只记录匿名汇总指标。

## 运行方式

- 快速搜索：20 秒时间预算。
- 深度搜索：60 秒时间预算。
- 请求按 2 秒间隔顺序执行。时间预算控制成本和限流风险，不把请求数或候选数写成产品能力上限。

先用人工选定的高信号关键词验收 CC98 搜索接口、候选解析、结果展示和限流边界。接入第三方大模型后，再对同一个查询依次运行原句基线和模型规划。合并候选池后，人工标记“相关”“部分相关”或“无关”。

## 通过条件

- 至少 80% 的查询在前五条中有一个明显有用的主题帖。
- 深度搜索找回人工候选池中至少 70% 的相关主题帖。
- 没有持续出现 `403`、`429` 或网络失败。
- 盲测结果达到相同门槛，且实现没有针对盲测查询增加专用规则。

如果所有查询规划器都无法达到 70% 候选池召回率，则查询时检索不适合作为通用搜索路线。后续应缩小产品承诺，或在取得授权后研究本地索引。

### 2026-09-14 首次在线观察

- 校园网直连下，`GET /me` 成功，扩展可以使用页面现有短期 access token。
- 一个开发查询的原句基线发送 1 次请求，耗时 0.1 秒，返回 0 个候选。
- 同一查询的本地快速规划在第 2 次请求收到 HTTP `403`，当时间隔为 450 毫秒；本轮没有候选。
- 这次观察只能证明 450 毫秒间隔过短，不能确定服务端允许的最小间隔。
- 下一轮把请求间隔提高到 3 秒，快速模式总时限提高到 20 秒。若仍出现 `403`，继续增加间隔，而不是重试或并发请求。
- 本地规划把领域短语拆开，并生成了低价值组合。决定停止堆叠中文硬编码规则，把它保留为失败对照；下一阶段改用第三方大模型生成检索词。

### 2026-09-14 高信号关键词冒烟测试

- 校园网直连下，人工选定一个高信号课程关键词，使用原句基线发出 1 次请求。
- 请求耗时约 0.1 秒，返回并成功解析 20 个候选，没有出现限制响应。
- 候选卡片正常显示板块、回复数、命中检索词数量和最佳排名。
- 前五条中存在明显有用的结果，因此这次接口与展示冒烟测试通过。
- 结果同时包含弱相关主题，说明后续仍需要模型查询规划和候选排序。本次结果不能单独证明自然语言查询的召回率达到目标。

### 2026-09-14 多词查询冒烟测试

- 校园网直连下，人工选定两个高信号约束词，以空格分隔后发出 1 次请求。
- 请求耗时约 0.1 秒，返回并成功解析 12 个候选，没有出现限制响应。
- 相比单个课程关键词返回的 20 个候选，多词查询明显收窄结果，前几名也更集中于两个约束的交集。
- 查询规划器应优先生成高信号词组，同时保留较宽的单词查询补充召回；具体数量交给模型按查询复杂度决定。
- 进一步加入学期约束后，1 次请求返回 1 个候选，耗时约 0.1 秒，没有出现限制响应；该候选符合目标语义。精确组合能显著收窄结果，但必须配合同义扩展避免漏召回。

### 2026-09-14 多请求合并测试

- 校园网直连下，手动提供 5 个用于模拟模型输出的检索词，按 3 秒间隔顺序请求。
- 5 次请求均成功，耗时 13.4 秒，合并去重后得到 19 个候选，没有出现限制响应。
- 多个候选被至少 2 个检索词同时命中，说明跨查询合并与重复命中统计正常。
- 与目标高度贴近的候选已经召回，但没有全部进入前五。候选召回和排序应拆开验收，后续不能只按重复命中次数排序。
- 下一轮把间隔降到 2 秒做受控测试。若出现 `403` 或 `429`，立即恢复到已验证的 3 秒，不继续向下试探。
- 2 秒间隔复测中，5 次请求均成功，耗时 8.4 秒，仍得到 19 个候选，没有出现限制响应。当前暂定 2 秒，不再继续压缩间隔。

### 2026-09-14 WebVPN 登录态观察

- 扩展能注入 WebVPN 内的 CC98 页面，并正确识别访问方式。
- 在同页完成登录后，隔离环境无法读取短期 access token；刷新后仍不可用。
- 新开页面出现的成功状态实际被识别为校园网直连，不能作为 WebVPN 路径通过的证据。
- 根据 CC98 的 `localStorage` 实现和 WebVPN 的站点隔离需求，推断 token 位于 WebVPN 页面环境的虚拟站点存储，而扩展隔离环境读取的是另一存储视图。
- 修复方案是在 WebVPN 页面环境中加入最小桥接，只读取短期 access token，并以同源页面消息交给扩展；不读取密码、Cookie 或 refresh token。该推断和修复必须经过真实 WebVPN 复验。
- 首次桥接复验仍未找到 token，因此上一条根因推断尚未成立。下一版只增加非敏感诊断：桥接是否响应，以及页面 localStorage 或 sessionStorage 是否存在 `accessToken` 字段；不报告任何值。
- 诊断版确认主页面桥接没有响应。下一版在不新增权限的前提下，尝试通过扩展公开资源加载同一桥接脚本，并区分“未执行”“消息未响应”和“页面策略阻止加载”。
- 公开资源桥接已执行，但 `window.postMessage` 在 WebVPN 页面中没有响应。下一版仅把通信改为共享 DOM `CustomEvent`，继续保持零额外权限。
- DOM 事件通信成功，但页面原生 localStorage 和 sessionStorage 均没有 `accessToken`。下一版只探测名称含 storage、vpn 或 wengine 的页面存储对象，并且只读取固定字段 `accessToken`；仅在找到唯一有效值时使用。
- 页面存储对象探测仍未找到 `accessToken`，随后原先偶发可用的新页面也无法再复现成功。至此停止零权限 WebVPN 认证试探。
- 当前验收结论：WebVPN 页面注入可行，但复用 CC98 登录态不可行，不能作为首版承诺。第一阶段使用已验证的校园网直连；RVPN 可作为系统级网络替代方案另行验证。若以后恢复 WebVPN 路线，必须单独评审新增脚本执行权限或独立认证流程的安全影响。

### 2026-09-15 Qwen3.8-27B 规划原型

- 本地 FastAPI 新增查询规划接口，通过 OpenAI 兼容的 Chat Completions API 调用 `qwen3.8-27b`（该后端已随旧探针一并删除）。
- 模型输入只包含自然语言查询。旧的外部候选重排接线已移除，个人背景、主题帖、回帖和认证数据不会进入模型请求。
- 规划输出包含检索词、必须概念及其表达、排除词和时间约束。检索词不设固定数量上限，后端对模型 JSON 做结构校验、日期校验和去重。
- 扩展按时间预算执行检索词并继续分页。候选重排在浏览器本地完成，必须概念优先于原始排名，并结合排除词、时间约束和跨查询命中。
- 人工标签在当前页面会话内按查询复用。匿名导出分别记录 Top-5 是否命中和相对于本会话全部已标记相关候选的候选池召回率，不包含候选标识或文本。
- 扩展清单只匹配校园网直连地址。WebVPN 桥接实验代码不再加载；失败记录保留在本文档中。
- 单元测试和静态检查已经覆盖模型请求边界、坏 JSON、空计划、本地服务转发和重排约束。
- 北京区真实模型调用已通过。合成查询要求查找 2025 年以来的高等数学期末资料并排除考研内容；接口返回 3 个检索词、1 个必须概念、排除词“考研”和起始日期 `2025-01-01`，HTTP 状态为 `200`。请求没有携带论坛候选或认证数据。
- 这次结果只验收模型规划链路。模型规划与 CC98 候选召回、本地重排的联合验收仍待在用户已登录的校园网直连 Edge 中执行。
