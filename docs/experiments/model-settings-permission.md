# 个人模型配置保存与试用提示验证

日期：2026-10-15。对应扩展版本：`0.3.5`。

## 问题与原因

用户在试用额度耗尽后填写个人模型 Key 与模型名称，保存时显示“未授予模型主机访问权限，设置没有保存”。

原实现先等待 `storage.get()`，再调用 `chrome.permissions.request()`。权限请求离开点击消息的同步调用阶段后，可能丢失浏览器要求的用户手势。浏览器返回的 `runtime.lastError` 未被读取，又将发起授权失败误报为用户没有授予权限。

[Chrome permissions 官方文档](https://developer.chrome.com/docs/extensions/reference/api/permissions)要求从用户手势中发起权限请求。

## 修复

- 首次填写 Key，或页面已知后台保存了 Key 时，在任何存储等待之前发起模型主机授权。
- `hasApiKey` 只用来决定何时发起授权。实际 Key 仍由后台读取，模型路径以保存的 Key 为准，返回页面的 Key 仍为空。
- 保留旧调用方不提供 `hasApiKey` 时的处理，以及 Key 留空保留原值的语义。
- 拒绝授权或授权调用异常时不覆盖原设置。读取 `runtime.lastError`，用不含凭据的提示区分浏览器无法发起授权与用户拒绝授权。
- 成功保存后的页面状态更新沿用现有逻辑。`hasApiKey` 变为 true 时，整张免费体验提示自动隐藏，无需新增关闭按钮。

## 复现与验证

后台回归测试先在旧实现失败。测试让本地存储回调结束模拟点击手势，以实际 `settings:save` 消息路径断言保存结果。修复后覆盖首次填写 Key、保留已保存 Key，以及拒绝授权和授权异常。

UI 测试连接真实 `createMessageHandler` 与 Shadow DOM 设置表单，使用合成 Key 和模型名称，覆盖额度耗尽后进入设置、提交配置和界面刷新。授权成功时，Key 与模型名称保存、输入框恢复为空、额度提示消失、搜索按钮可用；授权失败时保留原设置和提示。

使用临时配置文件加载构建产物，在隔离 Chromium 中拦截论坛页面与试用服务，全部替换为合成数据。仅在临时副本中将 Shadow DOM 改为 open 供测试定位。对原生授权调用进行对比：

- 将原生授权延后到存储 Promise 完成之后，实际收到 `This function must be called during a user gesture`。
- 按修复后的顺序调用原生授权，已发起请求，未收到上述错误。原生授权等待用户确认，未在自动化中点击允许。

已运行 `npm run typecheck`、后台与 UI 的 47 个测试，以及 `npm run build` 和构建产物检查。发布准备继续运行项目完整的 `npm run check`，结果以本次准备命令输出为准。

未使用真实论坛登录态、真实 Key 或真实模型调用，也未完成 Windows Edge 原生权限弹窗允许后的人工验证。步骤见[手动验收](../manual-acceptance.md#个人模型保存与试用提示)。
