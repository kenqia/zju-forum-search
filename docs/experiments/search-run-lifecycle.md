## 实现与 seam

- 页面通过 `SearchRun.start`、`stop`、`refreshTrial`、`dispose` 与状态输出操作搜索运行。运行代次、异步初始化、设置快照、收尾等待与额度刷新顺序集中在 `search-run.ts`。检索策略继续由 `SearchSession` 拥有。
- 继续使用已有 `RuntimeMessenger` 和来源 session 作为 adapter。测试通过运行的 interface 以及后台消息入口验证行为，不替换 `SearchSession` 的 implementation。
- 后台 `planner:begin` 保存设置快照，按页面文档和运行隔离。`planner:finish` 等待该运行的在途调用，再完成试用收尾和清理快照。失败的试用收尾可以重试。
- relay 的 finish 等待运行调用完成并释放锁。等待期间及时返回响应头，后台继续保活。没有数据库结构迁移。
