# 赞助试用通过项目服务调用模型

赞助试用于 2026-10-14 启用，已通过公网 HTTPS 验证真实模型的首轮、反馈和重排。用户已确认下面的方案。

当前扩展直接使用用户填写的模型 API Key。要让新安装者免配 Key 试用，又不暴露项目方的 Key，赞助试用的模型请求改由项目服务转发；服务端记录匿名试用额度，用户自带 Key 的现有调用方式继续可用。

项目服务只接收现有模型请求允许的查询和候选元数据，不接收论坛登录态、作者、正文、回帖或原帖地址。匿名资格不等同于真实用户身份，因此服务还需要独立的总支出限制；五次试用额度本身不能限制项目总账单。

## 首发约定

原拟使用 OpenAI 官方 `gpt-6-luna`。[OpenAI API 支持地区清单](https://developers.openai.com/api/docs/supported-countries)不包含中国大陆，并提示在清单外地区访问或提供服务可能导致账号受限。首发沿用百炼 `qwen3.8-27b`，以后可由项目方更换兼容模型。

项目方通过服务端环境配置手动选择供应商、端点、模型和 API Key，不必为更换赞助模型更新扩展。首发只接入 OpenAI 兼容的 `/chat/completions`，不提供管理网页或自动供应商切换。试用用户不能指定服务端上游地址或提示词。用户配置了自己的模型 Key 时优先使用现有直连方式。启用新模型前须核对地区支持、请求参数、JSON 输出和人民币计费单价。

每份匿名资格一次性获得五次完整搜索。首轮模型响应成功后消耗一次；在此之前模型或服务故障则返还。首轮响应后即使用户取消或站点检索失败，也不返还。

日预算为 ¥20、月预算为 ¥100，按上海时区计数。服务端在每次模型调用前预留输入和输出的费用上界，再按供应商返回的用量结算；用量未知时保留预留费用。不能在预算内预留的请求直接拒绝，包括正在进行的搜索的后续调用。单次搜索累计预算为 ¥1.5。预算依赖项目方填写正确的价格，供应商额外收费或配置错误不在服务端账本的保证范围内。

服务端不保存原始查询、候选元数据或模型回答，只保存匿名资格的哈希、额度、短期运行计数和汇总费用及错误统计。匿名资格存在扩展本地；重装可以重新获得资格，因此不能把这套方案宣传为每人五次。

首发赞助试用只开放 CC98，朵朵继续使用自带 Key。试用保留首轮规划、反馈和最终列表重排，站点请求次数最多为 30，最终重排最多 30 个候选。自带 Key 用户仍使用原有的 1 至 100 次设置。服务端最多允许一次首轮、30 次反馈和一次最终重排，每次模型调用限制输出 1200 tokens，并独立等待最多 60 秒。同一安装同时只能调用一次赞助模型；新搜索会结束之前闲置的运行。

服务端按匿名资格计五次额度，并对明显突发的同源请求做宽松限速；IP 不作为用户身份，避免校园共享出口让正常用户共用一份额度。每个来源 IP 每分钟最多 120 次请求，全服务每日最多发放 1000 份新资格，同时最多处理四次模型调用。

## 部署和回滚

采用单进程 Node.js 24 服务与 SQLite 文件，不增加数据库服务器。服务端复用扩展的 PlannerClient 和负载过滤，使用项目已有的 Vite 构建。Node.js 24 的 [node:sqlite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html) 仍属于实验接口；部署固定在 24.x 并运行重启和持久化测试。这比新增独立数据库更适合当前的一台小型服务器。多进程部署需要重新处理运行锁，首发不支持。

试用服务立即返回响应头，Nginx 关闭响应缓冲；扩展仅在模型请求期间每 20 秒调用一次存储 API，避免 [Chrome service worker 的 30 秒限制](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)提前结束请求。

用户选择完成验证后直接公开上线，跳过限量试点。已有腾讯云上海轻量服务器可用于部署；旧 OpenClaw 不再需要保留，用户不要求备份。实际迁移前仍须核对系统、进程和端口，不能据此假定服务器已清理。

试用域名为 `api.kenqia.top`。用户已确认完成域名解析、防火墙和备案核对；公网 DNS、HTTP 证书验证和 HTTPS 健康检查均已通过。服务器通过 SSH 部署，HTTPS 使用 Certbot webroot 证书与自动续期。

暂停赞助试用可在独立的 `/etc/zju-search/trial-switch.env` 中设置 `TRIAL_ENABLED=false` 并重启服务，自带 Key 路径继续可用。该文件通过 systemd drop-in 在密钥配置之后加载，覆盖密钥文件中的开关。调整开关无需读取或改写密钥文件。更换服务端配置前由运营者保留旧配置，回滚时恢复配置和构建产物，保留 SQLite 账本，避免再次发放已消耗的额度。具体步骤见[部署说明](../sponsored-trial-deployment.md)。
