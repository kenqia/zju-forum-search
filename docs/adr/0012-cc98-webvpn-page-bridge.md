# CC98 WebVPN 页面桥接

状态：已接受

日期：2026-09-23

## 背景

CC98 的 WebVPN 映射页与直连页使用不同的存储环境。扩展在隔离环境中读不到映射页的 CC98 登录凭据，直接改写搜索 API 地址仍会得到未登录响应。此前从页面存储读取凭据的试验没有成功；用户随后确认，在映射页观察论坛自身请求可以复用登录态并完成检索。

## 决定

只在 CC98 的 WebVPN 映射路径，于 `document_start` 加载 MAIN 环境脚本。脚本观察论坛的 `fetch` 请求，将其中的短期 Bearer 授权保存在页面脚本闭包内。隔离环境通过 DOM 事件请求它代发 CC98 搜索。事件包含搜索地址、响应状态和结果，不包含授权。搜索结果链接仍指向 WebVPN 映射页。

桥接只接受固定的 CC98 搜索路径及 `keyword`、`from`、`size=20` 参数。它一次只发出一条请求，持续速率约为每 2 秒一条，并允许一次快速重试。用户设置的单次搜索请求上限仍由 `SearchSession` 执行。URL 和事件名放在同一份 TypeScript 协议文件中，Vite 分别打包隔离环境和 MAIN 环境脚本；扩展清单继续加载生成的 `cc98-webvpn-bridge.js`。

## 边界与回滚

DOM 事件不是可信调用通道。同一映射页上的其他脚本可以触发桥接请求、观察响应或伪造响应；桥接的参数和速率限制只约束代发请求，不能认证事件发送方。若要消除这一限制，需要重新设计认证通道。当前实现不把授权写入扩展存储，也不通过 DOM 事件传送授权。

若桥接影响 WebVPN 页面，可移除该映射路径的 MAIN 脚本和搜索入口，保留 CC98 直连与 RVPN 访问方式。此回滚不需要迁移浏览器设置或凭据。

## 验证

合成测试覆盖授权捕获、参数校验、请求速率和并发限制，构建检查确认生成桥接脚本。用户已在真实 WebVPN 登录会话中确认基础检索可用；新增限流仍需在真实会话中复验。
