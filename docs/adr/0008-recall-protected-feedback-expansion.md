# 用可验证的反馈扩展保护召回

状态：已接受

日期：2026-09-21

当首轮只找到少量无关候选时，旧流程不会触发盲扩展，又会因为缺少相关性等级 2 或 3 而丢弃所有后续检索词。模型还可以在一个满 20 条的首页后终止运行，导致已知尚有分页却不再请求。这两种情况都会让少量弱命中比完全零命中更难恢复。

## 决定

仅匹配标题的来源使用由精确词、平衡词和宽锚点组成的首轮查询组合。组合至少包含一个宽锚点和一个非宽锚点，但不设固定总数。模型没有给全两类角色时，系统仍执行已有计划并提示组合不完整。查询角色只保证不同颗粒度的检索词获得首页机会，不影响候选排序。请求上限至少为 3 且首轮可能耗尽预算时，在执行一个宽锚点和一个非宽锚点后预留一次站点请求给救援检索词。

反馈轮使用无候选、弱信号和正信号三种状态。无候选和弱信号都可以在一次运行中执行一次查询依据救援；只有合法且首见的救援词进入队列才算消耗这次机会。独立的盲扩展模型调用被删除，空候选反馈与弱信号反馈共用同一协议。

后续检索词必须声明依据。查询依据扩展只能用于尚未消耗的救援。证据依据扩展最初要求每个引用键都在同一反馈中被判为等级 2 或 3。Issue #34 后由 ADR-0009 放宽为受限的 `clue_only` 规则。系统仍逐条校验扩展，不用一个正信号为整批新词背书。`learned_terms` 从协议中删除，因为通过校验的证据依据检索词已经表达同一事实。

模型的停止信号只是关闭后续扩展的建议。救援尚未使用、仍有检索词尚未首次执行，或本轮已产生合法的首见检索词时，本地停止门不接受该建议。一旦接受，本次运行不再重新开启扩展，但仍完成已知分页，并继续用反馈轮判断新候选的相关性。

CC98 保持每页 20 条，不假设服务端支持更大的 `size`。任意非空页都会产生后续分页，直到空页、时间提前停止、用户停止、来源错误或请求上限。请求上限在分页耗尽前到达时，界面必须把结果标记为部分结果。

作者保留在本地候选和结果卡片中，但不再进入反馈或最终列表重排的模型请求，作者变化也不触发模型重判。板块是相关性判断信号，但不是标题检索扩展的词汇来源。回复数不能单独提高相关性等级，只在最终列表重排中作为弱破同分信号。

模型超时、网络失败或响应无效时，系统保留已有候选并回退到本地逻辑，不为修复流程追加模型调用。

## 交付分期

Issue #30 实现首轮查询组合、证据依据扩展校验和作者元数据边界。查询依据扩展只进入协议和规范化结果，当前搜索运行不执行。无正信号救援、请求预留、停止门和新的分页终止规则留给后续任务。

Issue #31 已实现剩余部分。空候选与弱信号统一进入 Feedback；搜索运行只在合法首见 query 扩展入队后消耗救援。`should_stop` 只关闭后续扩展，已知首页和分页继续执行。CC98 的任意非空原始响应页都会生成下一 offset，直到空页或其他本地停止条件。

## 取代关系

本决定取代 ADR-0004 中“只有首轮全部零候选才盲扩展”和模型可以直接终止运行的规则，也取代 ADR-0007 中“本批存在任意等级 2 或 3 就放行全部扩展”的实际执行语义。ADR-0004 的固定首轮约束和模型数据边界继续有效，但作者不再属于允许出域的字段。ADR-0007 的反馈证据选择、软隔离和单次最终列表重排继续有效。
