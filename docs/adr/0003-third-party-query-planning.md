# ADR-0003：第三方模型只做查询规划

- 状态：模型数据边界保留，端点与密钥方案由 ADR-0004 取代
- 日期：2026-09-15

## 背景

本地通用分词会拆开课程名和校园领域短语，生成的组合也缺少稳定的检索价值。人工检索词已经证明多请求召回可行，但无法直接服务自然语言查询。

把论坛候选交给外部模型重排会扩大数据离开本机的范围。查询规划只需要用户输入，不需要主题帖、回帖、认证信息或个人背景。

## 决策

- 使用 `qwen3.8-27b` 生成查询计划，通过阿里云 Model Studio 的 OpenAI 兼容接口调用。
- 本地 FastAPI 保存 API key 并调用模型。扩展只能请求 `http://127.0.0.1:8000/*`，不会读取 API key。
- 当前原型的模型输入只包含自然语言查询。个人背景字段暂不接入，避免自由文本意外携带姓名、学号、账号或认证数据。
- 查询计划包含检索词、必须概念及其表达、排除词和时间约束。数组不设置固定数量上限，本地后端负责结构校验和去重。
- CC98 候选留在浏览器中。本地重排检查规划约束、标题和元数据，并结合 CC98 原始排名与跨查询命中。
- 删除生产接线中的外部候选重排。任何恢复论坛内容外发的方案都需要新的 ADR 和用户确认。

## 密钥与权限

API key 只写入被 Git 忽略的 `backend/.env`，文件权限设置为仅当前用户可读写。仓库只保留空值的 `.env.example`。

扩展新增 `http://127.0.0.1:8000/*` 的主机权限。该权限只用于连接本机规划服务。回滚时删除这条权限、后台脚本和 FastAPI 规划路由即可，CC98 原句与手动检索仍能运行。

## 影响

- 模型能够处理简称、同义表达和时间条件，查询规划不再依赖中文硬编码规则。
- 模型提供方会收到用户查询。用户需要按自己的账号地域配置对应的 API base URL。
- 搜索质量仍受 CC98 关键词接口影响。模型不能补回接口无法召回的主题帖。
- 排序质量由本地规则决定，需要与候选召回分别验收。
