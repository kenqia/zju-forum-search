# ADR-0004：采用模型反馈的迭代搜索，允许主题帖元数据出域

- 状态：已决定
- 日期：2026-09-15

## 背景

ADR-0003 把第三方模型限定为一次性查询规划：模型只接收自然语言查询，输出一组检索词后不再参与。可行性实验暴露出一次性规划的召回天花板——首轮检索词若没猜中论坛实际用语（简称、行话、技术词汇），后续排序再好也找不回未召回的帖子。

经典检索中的 Pseudo Relevance Feedback（PRF）用排名靠前文档的词扩展查询；本方案让 LLM 承担语义分析角色：平台作为召回引擎，本地执行有界的迭代搜索循环，每轮把新增候选的主题证据交给模型，学习下一轮检索词。

这改变了 ADR-0003 的数据边界：反馈轮的模型输入必须包含候选主题帖信息。

## 决策

- 搜索采用迭代循环：首轮由模型根据自然语言查询和论坛术语文表生成检索词；之后每轮把**本轮新增候选**的主题证据发回模型，模型追加新检索词或建议停用低效词，直到模型判断停止、无新候选或搜索预算耗尽。
- 允许出域的主题证据字段：标题、作者、发布时间、板块、回复数。仍然禁止出域：主楼正文、回帖内容、认证数据、用户身份与个人背景。反馈请求的数据结构只包含上述白名单字段，物理上无法携带正文或回帖。
- 首轮确定的必须概念、排除词、时间约束全程固定，反馈轮不得修改。
- 不预设固定轮次数和每轮检索词数；停止条件为模型 `should_stop`、候选池饱和（新增候选枯竭）、检索词折叠去重后为空或搜索预算耗尽。总 CC98 请求数设硬上限兜底。
- 第一轮全部检索词零候选时，执行一次无主题证据的盲扩展轮；仍空则按「没有找到主题帖」收尾。
- 「重新规划」清空全部反馈历史与候选集合，回到第一轮。

## 影响

- 优点：能学习论坛真实用语，突破首轮词汇猜测的召回天花板；每轮结果可增量展示；成本由搜索预算和请求上限共同约束。
- 限制：主题帖标题、作者等元数据会发送给第三方模型提供方，用户在界面文案中需要可见此边界；存在 query drift 风险（反馈链跑偏），靠固定约束字段和候选本地重排缓解。
- 待验证：CC98 `/topic/search` 是否返回作者字段；搜索结果是否包含「标签」；模型学到的术语（尤其英文技术词）能否被 CC98 服务端召回。
- 取代关系：本决策取代 ADR-0003 的一次性规划、固定模型和 FastAPI 密钥方案。ADR-0003 的首轮计划结构、本地重排和正文回帖不出域规则继续有效。若以后要把主楼正文或回帖纳入模型输入，需要新的 ADR。

## 补充：模型端点由用户配置（2026-09-15）

- 模型提供方不再固定为阿里云 `qwen3.8-27b`。用户在扩展设置中填写三项：OpenAI 兼容 base URL、API key、模型名称。
- 扩展 service worker 直接请求模型端点，本地 FastAPI 规划代理退役；API key 只保存在浏览器扩展存储中，不写入仓库、不进入页面 DOM。
- 反馈轮与首轮使用同一用户配置的端点。service worker 负责 JSON 解析与结构校验，模型不返回合法结构时按规划失败处理。
