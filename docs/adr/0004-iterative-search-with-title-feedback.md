# ADR-0004：采用模型反馈的迭代搜索，允许主题帖元数据出域

- 状态：已决定
- 日期：2026-09-15

## 背景

ADR-0003 把第三方模型限定为一次性查询规划：模型只接收自然语言查询，输出一组检索词后不再参与。可行性实验暴露出一次性规划的召回天花板——首轮检索词若没猜中论坛实际用语（简称、行话、技术词汇），后续排序再好也找不回未召回的帖子。

经典检索中的 Pseudo Relevance Feedback（PRF）用排名靠前文档的词扩展查询；本方案让 LLM 承担语义分析角色：平台作为召回引擎，本地执行有界的迭代搜索循环，每轮把新增候选的主题证据交给模型，学习下一轮检索词。

这改变了 ADR-0003 的数据边界：反馈轮的模型输入必须包含候选主题帖信息。

## 决策

- 搜索采用迭代循环：首轮由模型根据自然语言查询和论坛术语表生成检索词；之后每轮把**本轮新增候选**的主题证据发回模型，模型追加新检索词或建议停用低效词，直到模型判断停止、无新候选或站点检索请求次数上限耗尽。
- 允许出域的主题证据字段：标题、作者、发布时间、板块、回复数。仍然禁止出域：主楼正文、回帖内容、认证数据、用户身份与个人背景。反馈请求只包含上述白名单字段；adapter 还须保证标题来源真实，不能将正文片段改名为标题后外发。正文派生的显示标题只留在本地，反馈标题为空。
- 首轮确定的必须概念、排除词、时间约束全程固定，反馈轮不得修改。
- 不预设固定轮次数和每轮检索词数；停止条件为模型 `should_stop`、候选池饱和（新增候选枯竭）、检索词折叠去重后为空或站点检索请求次数上限耗尽。总请求数同时受站点硬上限兜底。
- 第一轮全部检索词零候选时，执行一次无主题证据的盲扩展轮；仍空则按「没有找到主题帖」收尾。
- 「重新规划」清空全部反馈历史与候选集合，回到第一轮。

## 影响

- 优点：能学习论坛真实用语，突破首轮词汇猜测的召回天花板；每轮结果可增量展示；CC98 请求量由用户请求次数上限和站点硬上限共同约束。
- 限制：主题帖标题、作者等元数据会发送给第三方模型提供方，用户在界面文案中需要可见此边界；存在 query drift 风险（反馈链跑偏），靠固定约束字段和候选本地重排缓解。
- 待验证：CC98 `/topic/search` 是否返回作者字段；搜索结果是否包含「标签」；模型学到的术语（尤其英文技术词）能否被 CC98 服务端召回。
- 取代关系：本决策取代 ADR-0003 的一次性规划、固定模型和 FastAPI 密钥方案。ADR-0003 的首轮计划结构、本地重排和正文回帖不出域规则继续有效。若以后要把主楼正文或回帖纳入模型输入，需要新的 ADR。

## 补充：模型端点由用户配置（2026-09-15）

- 模型提供方不再固定为阿里云 `qwen3.8-27b`。用户在扩展设置中填写三项：OpenAI 兼容 base URL、API key、模型名称。
- 扩展 service worker 直接请求模型端点，本地 FastAPI 规划代理退役；API key 只保存在浏览器扩展存储中，不写入仓库、不进入页面 DOM。
- 反馈轮与首轮使用同一用户配置的端点。service worker 负责 JSON 解析与结构校验，模型不返回合法结构时按规划失败处理。

## 补充：固定模型延迟与显式时间过滤（2026-09-15）

- 首轮、盲扩展和反馈轮统一关闭思考模式，并把最大输出限制为 1200 tokens。该行为是固定策略，不提供用户选项。
- 每次模型调用由独立的 `AbortController` 限制为 20 秒。超时与网络错误使用不同的停止原因；反馈超时保留当前结果。
- 用户设置只控制站点检索请求次数上限。站点请求之间的最小间隔继续生效，模型调用不计入站点请求次数。
- 扩展把浏览器当前日期发送给规划器，用于解析“近三年”“去年”等相对时间。模型返回的起止日期必须通过本地格式、日历日期和先后顺序校验。
- 只有用户明确提出时间条件时才执行硬过滤。确定在范围外的帖子不进入主排行榜或模型反馈证据，界面只显示忽略数量；发布时间未知的帖子保留。没有明确时间条件时不按发布时间过滤。

## 补充：查询计划规范化与原词兜底（2026-09-16）

- 模型继续使用 JSON Object 输出，不要求端点支持 JSON Schema。浏览器先规范化模型结果，再校验业务约束。
- 缺失的 `purpose`、`required_concepts`、`excluded_terms` 和无时间查询的 `time_constraint` 使用安全默认值；字符串形式的 `searches` 转换为标准检索词对象；空的必须概念被丢弃。
- 硬校验只保留可用检索词和时间范围。没有可用检索词时报明确错误，时间值非法、顺序颠倒或不符合用户时间条件时报时间范围错误。
- 纯单关键词的模型计划无法恢复时，直接用用户原词执行 CC98 搜索，并在进度区持续显示兜底提示。模型超时、网络错误、HTTP 错误和自然语言长句不使用该兜底。
- 进度区把累计零命中的已执行词显示为「未命中检索词」。`learned_terms` 不进入执行队列，因此不再展示；真正的后续检索词来自 `new_searches`。

## 补充：相关性等级主导本地预排序（2026-09-20）

- 明确时间条件是硬约束。确定越界的候选不进入主结果、软隔离区域或反馈证据；发布时间未知的候选保留。没有明确时间条件时不按发布时间过滤。
- 通过时间约束的 active candidates 先比较相关性等级。grade 3 高于 grade 2，grade 1 与未判断候选同级，grade 0 只进入软隔离区域。
- 同一语义层级内依次比较排除词命中、必须概念覆盖、不同折叠检索词数量、来源最佳位次和首次命中轮次。排序文档仍逐份匹配，不能把不同片段拼成一次命中。
- 标题和候选身份只用于最终确定性平局。模型阶段关闭、取消或失败时，结果完整保留本地预排序。
