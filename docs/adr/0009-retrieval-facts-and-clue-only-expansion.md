# 向模型提供检索事实并允许 clue-only 扩展

状态：已接受

日期：2026-09-22

反馈轮和最终列表重排已经能读取候选元数据，但看不到浏览器掌握的检索过程。最终重排无法区分多词重复命中的候选和单次尾部命中的候选。反馈轮也无法比较各检索分支的页数、产出和边际新增。另一个限制是等级 1 候选不能提供下一跳线索，即使标题暴露了有用的站内叫法。

## 决定

最终列表重排为每个候选增加三项检索事实：最多 5 个按首次观察顺序保留的不同命中检索词、基于全部观察计算的独立检索词数量，以及全部合法正位次中的最小值。没有已知位次时发送 `null`。相关性等级继续留在本地，删除保护不变。

反馈轮增加剩余站点请求数和 Search Ledger。Ledger 为每个已执行检索词记录页数、累计原始命中数、分支去重候选数、最近一页合并前带来的全局新候选数、分支候选当前等级 2/3 与等级 0 的数量，以及是否仍有 continuation。同一候选可以计入多个分支。统计只存在于当前搜索运行。

完整 Feedback JSON 继续受 4000 UTF-8 字节限制。序列化先装入查询、当前日期、剩余请求数、Ledger 和已执行检索信息，再装候选证据。单个条目放不下时跳过该条目，继续尝试后面的条目。反馈候选的 `matched_queries` 仍最多为 3 个。

证据依据扩展增加可选的 `clue_only`。支持集合包含等级 2 或 3 时按普通扩展接受，集合中可以同时有等级 1。支持集合全部为等级 1 时，只有 `clue_only: true` 才能通过。等级 0、未知键、不在本次 Feedback 负载中的候选，以及没有模型可见原生标题的候选不能提供支持。

本地校验只确认支持关系、当前等级和标题可见性。它不要求扩展词是标题子串，也不计算词元重叠或语义相似度。比如标题“老师突然说这学期换书了”可以支持 `clue_only` 查询“教材更换”。词义转换仍由模型负责，本地只验证来源。

## 影响

模型获得更多运行内事实，但没有新增站点请求或帖子内容读取。Search Ledger 和 Final Rerank 检索事实都来自已有观察。作者、URL、平台标识、正文、回帖、片段、轮次和认证数据仍不出域。

Ledger 会占用固定负载预算，因此复杂搜索能装入的候选证据可能少于用户设置的数量上限。这是有意取舍。模型先看到完整搜索状态，再使用剩余空间判断候选。

本决定取代 ADR-0008 中“等级 1 永远不能支持证据扩展”的规则。ADR-0007 的反馈候选选择、软隔离和最终重排删除保护继续有效。
