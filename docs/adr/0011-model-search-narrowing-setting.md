# 允许用户关闭模型自动收窄搜索范围

状态：已接受

日期：2026-09-22

## 背景

反馈模型有两条减少后续搜索范围的控制路径：`should_stop` 关闭未来扩展，`stop_queries` 删除已执行检索词的下一页 continuation。默认启用它们可以减少低价值请求，但需要高召回的用户应能把已配置的站点请求次数预算更多地用于继续搜索。

## 决定

在现有模型设置中增加 `modelSearchNarrowingEnabled`，默认值为 `true`。缺失、非布尔或无效的旧值都规范化为 `true`，以保持升级前行为。

搜索创建 `SearchSession` 时读取一次该值，作为整个运行的固定快照。关闭时：

- 本地忽略 `should_stop`，不关闭后续扩展；
- 本地忽略 `stop_queries` 及兼容字段 `stop_suggestions`，不删除 continuation；
- 仍接受经过现有校验的 `new_searches`；
- 仍受来源耗尽、时间提前停止、请求次数上限、错误和用户取消约束。

Feedback prompt 在关闭时要求模型返回 `should_stop: false` 与 `stop_queries: []`，但 prompt 不是产品边界，本地执行保护始终有效。设置修改只影响下一次搜索。

## 取舍

不新增隐藏预算或“搜索更多”操作。用户可见的站点检索请求次数上限仍是唯一硬预算；关闭开关只是移除模型主动减少范围的能力，不承诺一定增加请求或结果数量。两条停止路径必须一起关闭，否则用户无法预测“关闭自动收窄”的实际效果。
