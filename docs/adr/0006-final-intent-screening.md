# ADR-0006: 请求上限、相对时间、批量意图筛选与来源排序提前停止

## 状态

已接受（随 issue #22、#23 落地）；最终意图筛选部分已由 ADR-0007 取代。下文保留当时的历史决策，不描述当前实现。

## 背景

迭代搜索可能召回数百条候选。此前的停止路径只按时间范围、必须概念和排除词做本地过滤，明显无关的结果仍留在列表里。CC98 搜索接口按发布时间倒序返回，朵朵按热度排序；当用户查询带明确起始日期时，CC98 继续翻页只会得到更旧的结果，继续请求是浪费。需要：

1. 让模型在搜索结束路径上做最终意图筛选，同时维持既有的模型数据边界。
2. 覆盖一次搜索的全部候选，而不是只有单批 160 条。
3. 在 CC98 上按排序声明提前停止分页，且不误伤朵朵的热度分页。

## 决策

### 1. 筛选输入延续白名单边界

- 新端口 `planner:screen` 走与 `planner:feedback` 相同的通道：content script → `chrome.runtime` → service worker → `chat/completions`。
- 每批只发送原始查询、批次临时键（`r0`、`r1`…）和白名单元数据：原生标题、作者、发布时间、板块、回复数。平台 ID、URL、正文、回帖、命中片段、认证信息和身份信息不外发；朵朵正文派生标题发送为空字符串。
- 白名单投影在 core 内完成（`screening.ts`），adapter 不提供 toScreening 方法；序列化时再次按白名单输出，字段路径与反馈轮一致。

### 2. 拆分与原子语义

- 每批最多 160 个候选，且 `{ query, candidates }` 序列化后不超过约 4000 UTF-8 字节；两条约束任一先满即封批。拆批不改变候选顺序，临时键按全局候选序号分配。
- 批次按顺序执行，复用每次模型调用 20 秒超时与 `AbortController` 取消。
- 只有全部批次成功且返回合法 `{ remove_keys: string[] }` 结构后，才合并去重临时键并一次性从结果列表移除。任何一批失败、超时、取消或返回无效结构，丢弃所有已收集的移除建议，保留筛选前的完整列表，并显示“意图筛选未完成”。
- 模型只能通过临时键指定移除对象；未知键被忽略，不会误删其他结果。
- 筛选前结果保持不变——筛选只删不排，移除后其余结果维持既有本地排序。

### 3. 触发与取消边界

- 默认开启，模型设置中可关闭。
- 有结果的正常停止路径（模型判断停止、无新候选、无新检索词、请求上限、限流等）和用户手动停止都会进入最终筛选；零结果运行和被新查询替换的运行不调用筛选。
- 新查询会取消旧筛选（同一 `AbortController`），旧筛选完成后不得写回新搜索状态——screen 结束后再查一次 `requestedStop === 'replaced'`。

### 4. 按来源排序声明提前停止

- `SourceCapabilities` 增加 `resultOrdering: 'time-desc' | 'other'`。CC98 声明 `time-desc`（可靠的发布时间倒序），朵朵声明 `other`（热度排序）。
- 仅当来源声明 `time-desc` 且查询解析出明确起始日期时，对每个检索词分别判断：当前页每条结果都有可解析的发布时间，且该页最新结果已早于起始日期，则该检索词不再翻页——倒序来源上后续页只会更旧。
- 页面含未知时间、空页、混合时间或仍有在范围内结果时不提前停止。该提前停止只作用于本检索词的游标推进，不取消其他检索词；所有请求仍共享用户请求次数上限。
- 朵朵不做时间排序提前停止，继续按热度分页。

### 5. 请求次数上限

- 用户设置一次搜索允许的站点 `search()` 调用次数，默认 30，范围 1 至 100；分页调用计入同一个上限。两个来源的 `maxSearchCalls` 均为 100，只承担设置范围外的安全兜底。
- 请求间隔继续由来源的 `minRequestIntervalMs` 控制。模型调用不计入站点请求次数，每次模型调用仍单独受 20 秒超时约束。
- 旧 `searchBudgetSeconds` 字段继续读写，便于旧版本或降级版本读取，但不再控制搜索，也不在界面显示。

### 6. 本地相对时间解析

- 浏览器按设备本地日历解析“最近”“近半个月”和近 N 天、周、月、年。天和周使用包含今天的闭区间，月和年按日历回退并在目标月份末尾截断。
- 本地解析成功时覆盖模型日期。无法本地识别的明确时间表达继续使用模型日期和原有合法性校验；发布时间未知的候选继续保留。

## 取舍

- 顺序逐批而非并发：行为可预测、可取消，且批次间共享同一取消信号；代价是多批时筛选总时长随批数线性增长。
- 原子应用而非逐批应用：避免“筛了一半”的中间态，代价是单批失败时全部建议作废。
- 提前停止只在 adapter 声明 `time-desc` 时启用：CC98 的倒序是实测行为，朵朵的热度排序无法推出时间单调性，宁可多翻页也不误停。
- 请求次数比运行时长更容易解释和复现，但单次搜索的实际耗时仍取决于来源间隔、网络和模型调用。界面因此显示请求计数，不承诺固定完成时间。
- 常见相对时间在本地解析，避免模型日期漂移；未覆盖的学期、节假日等表达仍交给模型，保留现有扩展能力。

## 回滚

- 设置项 `intentFilterEnabled` 关闭即绕过全部筛选路径，回到 issue #21 的结束行为。
- 将 `CC98_CAPABILITIES.resultOrdering` 改回 `'other'` 即停用提前停止，分页行为回到满页推进。
- 移除 `planner:screen` 消息类型并还原 `SearchSession.finish` 为同步收尾即可整体回退；筛选不改动候选数据本身，无持久化副作用。
- 请求次数控制可通过回退 issue #21 的 session 变更恢复旧时长控制；保留的 `searchBudgetSeconds` 使旧版本仍能读取原设置。该回退会重新启用旧时长语义，必须同步恢复设置界面和文案。
- 本地相对时间解析可独立停用，查询计划会继续使用经过校验的模型日期，不需要迁移存储数据。

## 验证

- `src/extension/search-session.test.ts`：请求上限、尾部 >20 条保留、重复游标不循环、整页早于起始日期提前停止、混合/未知时间不误停、朵朵热度源不触发时间捷径、单批与多批移除、失败原子保留、replaced/禁用跳过、白名单元数据边界。
- `src/extension/planner.test.ts`：最近 30 天、近半个月、中文数字、月末、跨年与闰年固定日期，以及本地日期覆盖模型日期。
- `src/extension/screening.ts` 拆批逻辑由多批测试覆盖：全部候选进入某个批次、键—候选对应不变。
- `npm test` 与 `npm run build` 全绿。
