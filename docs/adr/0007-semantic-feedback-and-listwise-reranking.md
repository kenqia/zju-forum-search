# 用逐轮语义判断和单次列表重排替代最终批量筛选

状态：已接受

日期：2026-09-20

当前实现先耗尽一轮检索词的分页，再让模型规划下一轮；反馈证据按新增顺序截断，本地排序也没有语义判断。搜索结束后的全候选批量筛选只会删除结果，候选越多，模型调用、等待时间和费用越高。这些行为会让反馈来得太晚，也不能改善前排结果。

## 决策

搜索改为广度优先的检索波次。同一检索词每个波次最多请求一页，新检索词和已有检索词的分页共享站点请求次数上限。新检索词优先取得第一次执行机会，分页请求不能长期饿死。一个波次产生可判断的新证据后才进入反馈轮；没有新证据时不做空模型调用。

反馈轮一次完成相关性判断、反馈证据准入、查询扩展和停止判断。返回结构包含候选临时键的 `0 | 1 | 2 | 3` 等级、`new_searches` 和 `should_stop`。`3` 表示明确高度相关，`2` 表示大概率相关，`1` 表示信息不足、部分相关或不确定，`0` 表示明确无关。只有 `2` 和 `3` 可以帮助模型学习新检索词；`1`、未判断候选和模型无法确认的候选都保留。

本地反馈证据选择先选从未判断的候选，再选因独立检索证据而需要重判的相关性等级 0，最后选择其他带新证据的候选。每个 priority 类别内部按最新独立证据所属检索词轮转，每个检索词先争取 2 条，随后在该类别内按本地预排序补满。2 条是公平目标，不是永久上限。存在有新独立证据的等级 0 候选时，每次反馈至少保留 1 个翻案名额；未使用的名额在候选不足时释放。单次候选数量由用户在 `10–100` 范围内设置，默认 30；模型负载仍受固定的 4000 UTF-8 字节上限约束，字节限制优先于数量限制。白名单和序列化阶段遇到过长候选时跳过该候选并继续尝试后续候选。没有进入本次选择或未装入负载的候选留到后续波次。

每次搜索运行按 `sourceId + platformPostId` 识别候选，并分配稳定的临时键。反馈轮可以看到每个候选最多 3 个不同的 `matched_queries`，但看不到来源位次、轮次、平台标识、URL、正文、回帖或认证数据。同一检索词下只有位次变化不构成独立检索证据；被不同检索词命中或白名单元数据发生变化时，相关性等级 0 才能重新进入判断。新判断覆盖当前等级，历史只供本地调试。

相关性等级 0 使用软隔离，不从运行内部删除。主列表隐藏它们，用户可以展开“已隐藏的明确无关结果”查看原结果卡片；查看不会恢复候选。只有新的独立检索证据和后续非零判断才能让候选回到主列表。

本地排序改为预排序，依次比较时间硬约束、相关性等级、明确排除词、必须概念、不同检索词命中数、来源最佳位次和首次命中轮次。`3` 高于 `2`，`1` 与未判断候选同级，`0` 隐藏。必须概念和其他词法规则不能压过模型已经给出的相关性等级。

删除全候选、多批次、只返回 `remove_keys` 的最终意图筛选。正常结束后，系统从主结果候选中取本地预排序前 M 条，只调用一次最终列表重排。M 默认 30，可在 `10–150` 范围内设置；关闭最终列表重排时控件禁用但保留原值。模型返回 `ordered_keys` 和 `remove_keys`，可以跨相关性等级调整顺序。相关性等级 0 不进入调用。相关性等级 1、2 和 3 只能排序，只有请求发出前仍未判断的候选可以接受移除建议。未返回的合法候选按本地顺序追加，Top-M 之外保持本地顺序。

用户主动停止站点检索后，如果最终列表重排开启且至少有两个主结果候选，仍执行最终列表重排。用户可以取消正在执行的重排，取消后立即保留本地预排序。新查询替换旧运行时取消旧运行，不执行重排。

模型超时、网络失败、非法 JSON 或无法识别的整体结构都采用召回优先的回退。反馈轮失败时停止迭代并保留未软隔离候选，直接使用本地预排序，不再追加模型调用。最终列表重排失败时也完整回退到本地预排序。合法响应中的未知键、非法等级和无效删除请求局部忽略，不扩大删除范围。

## 取代关系

本决策取代 ADR-0004 中“整轮检索结束后只做查询扩展”的反馈职责，以及 ADR-0006 中“覆盖全部候选的多批次最终意图筛选”。ADR-0004 的模型数据白名单、固定首轮约束和盲扩展规则继续有效；ADR-0006 的站点请求上限、相对时间处理和按来源排序提前停止继续有效。

本次不建立正式离线评估体系，验收以实际搜索体验为准。帖子标题的提示注入风险，以及 CC98 与朵朵反馈证据能力差异，不在本决策范围内。
