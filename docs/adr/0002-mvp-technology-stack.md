# ADR-0002：MVP 采用 FastAPI + React/Vite，并保留模型提供方边界

- 状态：已决定
- 日期：2026-09-05

## 背景

MVP 需要一个本地网页界面来输入自然语言查询、展示匹配原因和跳转链接；后端需要调用 CC98 官方 API，并在本机完成候选结果处理。中文文本处理和后续检索实验需要保持较低的试错成本。

## 决策

- 后端使用 Python + FastAPI。
- 前端使用 React + Vite + TypeScript。
- 第一版的查询理解采用简单规则、关键词组合和本地重排，不调用外部 LLM 处理帖子正文。
- 代码预留模型提供方接口，使未来可以接入外部 LLM。当前本地实验允许通过显式开关发送候选主题帖和全部文字回帖；该开关默认关闭，不写入公开部署配置。
- CC98 多请求实验使用受控开关、并发和总请求上限；收到 `403`、`429` 或其他限制信号时立即停止。生产默认策略不依赖未经验证的并发行为。

## 影响

- 优点：前后端职责清晰；本地开发和中文检索实验成本低；未来可以替换模型提供方。
- 限制：需要维护两个开发运行时；第一版语义理解能力有限；多请求实验不能保证提升召回率。
